# Мастер CRM — API

NestJS 12 + PostgreSQL (Prisma 7) + бот на grammY в том же процессе.
Устроен так же, как API репетиторов (saas/api): вход по initData Telegram,
JWT, всё скоупится по `masterId`, деньги — целые копейки.

## Запуск локально

Нужен Postgres (brew services start postgresql@17) и база:

```bash
psql -d postgres -c "CREATE ROLE beauty LOGIN PASSWORD 'beauty' CREATEDB"
psql -d postgres -c "CREATE DATABASE beauty_crm OWNER beauty"
cp .env.example .env      # BOT_TOKEN и JWT_SECRET — см. комментарии
npm install
npx prisma migrate dev
npm run seed:demo         # демо-клиентки и записи для dev-мастера (tgId 100000001)
npm run start:dev         # http://localhost:3002/api (порт из .env)
```

Локально `BOT_MODE="off"`: бот не подключается к Telegram и никому не пишет,
а токен в `.env` нужен только для подписи initData. Фронт (`npm run dev` в корне)
входит без Telegram: dev-сервер подписывает initData тем же токеном.

```bash
npm test                  # чистая логика: подпись, напоминания, пересечения, фото
```

## Что есть

| Роут | Что делает |
|---|---|
| `POST /auth/login` | Вход по initData. Первый вход создаёт пустой кабинет |
| `GET/PATCH /master` | Имя, направления, рабочий день, интервалы напоминаний. Новое направление добавляет в прайс свои стартовые услуги |
| `GET /master/specialties` | Каталог направлений: ногти, брови, ресницы, волосы, макияж, косметология, массаж, депиляция |
| `/services` | Прайс: CRUD, удаление = убрать из прайса |
| `/clients` | Карточки клиенток: форма, что любит, аллергия, оплата, раз в сколько недель коррекция |
| `/clients/:id/photos` | Фото работ: JPEG/PNG/WebP до 1,5 МБ, тип проверяется по содержимому |
| `POST /clients/:id/invite` | Ссылка в бота: после «Начать» клиентке приходят напоминания |
| `/appointments` | Записи. Сервер сам считает длительность и цену по прайсу, хранит снимок услуг и не даёт записать на занятое время (409) |
| `POST /stories`, `GET /stories/:id.jpg` | Картинка «Окошки в сторис»: Telegram публикует сторис только по публичной ссылке. Хранится в памяти 15 минут, только JPEG, у мастера — три последние |
| `GET /windows?from&to`, `PUT /windows` | Ручные правки окон для сторис на месяц: какие часы мастер убрал или добавил к расчёту. Сами окна считает мини-апп из рабочих часов, `workDays` и записей |

**Направления** (`src/specialties/specialties.ts`) задают не логику, а слова
и стартовые данные: прайс, обычный интервал между визитами, подпись поля
карточки («Форма бровей», «Тип кожи») и то, что бот пишет через N недель —
«пора на коррекцию» для ногтей, бровей и ресниц, «самое время записаться снова»
для остальных. Новое направление — правка этого файла, без миграции.

**Напоминания** (планировщик раз в минуту): за `notifyBeforeHours` и
`notifyBeforeMinutes` до визита (по умолчанию за день и за 2 часа) с кнопками
«Приду ✓» / «Не смогу». Ответ виден мастеру в приложении, об отказе бот пишет
мастеру сам. Через `repeatWeeks` после визита — «пора на коррекцию», если
клиентка так и не записалась. Ночью (22:00–09:00 по поясу мастера) бот не пишет.

## Чего пока нет

- лист ожидания и рассылка свободного окна;
- напоминание о долге — «Напомнить» в «Деньгах» открывает чат с клиенткой;
- правка карточки клиентки и рабочего дня во фронте (API готов);
- регулярные записи «каждые 3 недели» — как серии в tutor-crm.

## Деплой

Как у API репетиторов: `npm run build`, `npm run start:prod` (миграции на старте),
`BOT_MODE="webhook"` с `BOT_PUBLIC_URL` и `BOT_WEBHOOK_SECRET`. Нужен отдельный
бот у @BotFather — не бот репетиторов.
